# ForgeDuet

工作流说明和 relay 运行时均为 **v0.4.0 候选版**。说明版本与运行时/游标版本分开，实测范围和接入限制见[验证记录](docs/VALIDATION.md)。

**额度续接的当前范围：Claude Code 桌面构建 + Codex App/queue 审查，这个组合还不能在额度重置后自动继续。** 真实桌面额度检测和重新唤醒接入尚未实现；现在交付的是有可信适配器回执时的等待/续接逻辑与合成测试，见[各模式可用范围](protocol/QUOTA_RESUME.md)。

**一个 AI 编码和自测，另一个 AI 审查和独立测试，用证据推动双方收敛。** 人类指定范围、模型和强度，提出需求，处理争议，并参与设备等现实环境验收。

这套方法来自多轮实际项目协作。价值在于审查方自己读代码、复现问题、提供不能随意改松的回归测试，以及编码方用反向验证证明修复确实被测试覆盖。两个模型赞同同一个结论，并不能代替证据。

## 包含什么

- [编码 + 测试技能](skills/forgeduet-build/SKILL.md)。
- [审查 + 独立测试技能](skills/forgeduet-review/SKILL.md)。
- [共享协议](protocol/PROTOCOL.md)、[启动清单](templates/SETUP.md)、[项目规则](templates/PROJECT_RULES.md)、交付与审查模板。
- 默认双向自动交接：每 1 分钟检查对方文件夹，配套共享锁、原子发布、完成标记、持久确认和只追加的更新日志。
- 默认先由本地脚本检查，无待处理输入时不调用任何模型，基础模型也不需要。配套 Python watcher 和可选 CLI 信箱/适配器；AI 定时唤醒会反复用模型，只能作为用户知情选择的后备方式。

两份技能都带齐协议和工具，可以各自复制安装。支持不同供应商的模型，不要求一定由某个品牌担任某个角色。

## 怎么开始

**先看[协作上手](protocol/MANUAL.md)和[自动交接](protocol/AUTO_HANDOFF.md)。** 用户启动一轮本机协作后，两边必须各自设置并验证监控：构建方盯 `reviews/`，审查方盯 `deliveries/`，默认每分钟一次；每次交付后确认已重新等待，不再让用户来回转述。默认顺序是：**本地哈希/完成标记/确认记录检查 → 待处理事件 → 已验证的客户端唤醒或 CLI 派发 → 选定的编码/审查模型**。使用确实能唤醒会话的后台任务，或配置好的 CLI relay；不要求一定装 CLI。缺少唤醒桥接能力要如实说明，不能改成每分钟先叫醒 AI 再查文件。AI 定时任务只能作为明确告知用量、由用户选择的后备方式。只修改或安装技能是准备工作，不启动或恢复任何项目。

网页版 ChatGPT 没有本机 Git 也可以参与：[快照交接](protocol/SNAPSHOTS.md)会导出指定提交的 ZIP 和清单，用完整 SHA 加压缩包 SHA-256 锁定版本。是否能核验哈希、执行测试，要按实际工具能力写清楚。

先记录启动选择：**两方各用哪个模型、什么推理强度、报告语言**，权限和预算。设置验证分为“已核实 / 自报 / 无法核实”，不再因为诚实地填“无法核实”就拒绝工作。实际设置不明要说明，不能擅自换模型或伪称核实。已有授权也不反复询问。

项目使用短命 feature 分支，审查方用独立 worktree 或已核验快照。每轮各写一份不可变 Markdown；共享写入和获准的记录提交前拿同一把 `.lock/`，追加 `updates.log` 后释放。记录带作者和时区时间，修改共享文档时保留更新表。锁不跨思考、测试或等待，也不自动删除对方的旧锁。当前范围内 P1/P2 阻止合并；允许延期的 P3 进路线图。新范围或争议交给人类。

[目录与记录归属](protocol/WORKSPACES.md)给出了协调、构建、审查三个目录的具体布局，单项目目录的报告写入例外，以及由谁提交记录。构建方显式读取用户认可的项目约定；Claude 示例仍保留安全模式，不自动加载项目 `CLAUDE.md`。

Codex 的项目安装位置是 `.agents/skills/`；Claude Code 可以放 `.claude/skills/` 或 `~/.claude/skills/`。每份技能都整目录复制。项目内安装可用于构建方；自动审查必须从构建项目和候选目录之外的可信技能副本启动。详细安装和[官方来源](README.md)见英文说明。

双方不是反复改同一份交付文档，而是每轮发布新报告。`handoff.py` 比较“报告路径＋文件内容 SHA-256”与**上次已处理并确认的哈希**，不是上次扫描结果；这样崩溃重启不会漏掉已见但未处理的报告。`updates.log` 和监控状态变化不触发产品审查。哈希变化只说明报告变了，完成标记只是发布者声明，仍需核对版本、范围和测试证据。本地 `handoff.py` 只把完整文件当成交付，兼容“交付完成。”等句末写法；无标记文件稳定两分钟后会提醒，但不会假装交付或自动记为已读。临时读错下轮重试，连续失败保留诊断并停止。醒来不等于已处理，确认输入哈希后才记为完成。客户端必须有真实的唤醒机制，光启动一个 Python 进程不够。设置后记录真实任务 ID/进程、验证证据和恢复方式；电脑休眠、会话关闭或额度耗尽可能中断它。双方同 SHA 批准与接受、需要人工、到达约定预算或用户叫停时停止。网页上传和人工转交是明确选择的后备方式，不是悄悄降级的默认方式。

需要 CLI 派发时看[通信说明](protocol/TRANSPORT.md)和[两个示例适配器](protocol/ADAPTERS.md)。有新任务才启动模型；真实 Claude/Codex CLI 接入尚未测试。本地 relay 仍使用 worktree；网页快照审查走明确的手动后备流程。示例审查适配器禁止自动加载候选配置：Claude 使用安全模式，Codex 从外部可信控制目录启动；详见适配器说明。

改规则现在只暂停新任务派发，当前任务按已保存的旧规则完成。人类确认采纳新规则后继续，并使旧批准失效。采纳和恢复都保留原任务、交付报告和消息链，人的决定另附；已暂停时采纳不派发，等待恢复。需要立即撤销权限时应显式暂停任务。两端 relay 的版本和文件哈希也会核对，防止不同版本混用信箱。

配置中的权限声明不能替代系统沙盒。Token/费用限额在任务之间检查，正在运行的一次调用可能超出预算；拿不到真实用量时，有限额的任务暂停等待人工处理。双方报告是数据，不是新的授权，更不能作为 shell 命令执行。

## 验证与发布

```sh
python3 -m unittest discover -s tests -v
python3 scripts/sync_bundle.py --check
```
