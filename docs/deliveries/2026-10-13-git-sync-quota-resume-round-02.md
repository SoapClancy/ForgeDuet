## FD-GIT-001（P2）：临时网络中断

`git_transport.py` 区分已识别的 DNS、连接、远程超时及临时消失的本地远端，与认证/完整性/冲突/未知失败。临时故障返回 retrying，不发停止通知、不退出 watch；按 interval 指数退避，默认上限 300 秒，连续 5 次真正失败后才停止并通知。失败次数、下次时间、历史和最终原因持久化；重启不清零，成功清除连续计数。预算/模型与此重试无关，不调用模型来探测网络。

`once` 的临时故障退出 0 并返回明确 retrying JSON，不能据此称同步完成。watch 在到期时再次尝试，push 仍只核对/重传原 pending Git 提交。耗尽后需明确 `resume --config ...`，不会清理 Git heads、pending 或任何 ack；最终原因和 incident 在重启后保持一致，只发一份该事件的通知。认证、数据不符、历史改写等仍立即停止。

独立自测：真实临时 bare 远端改名造成离线，运行中的 watch 仍存活；远端恢复后自行继续导入。另测 once 结果、持久退避/计数、重启、阈值退出与显式恢复、认证不重试、只对远程命令超时重试、损坏状态不覆盖。

## FD-GIT-002（P2）：本机停止通知误作远程交付

构建方通知写本机 **reviews/**，审查方通知写本机 **deliveries/**，让本机角色检测器看到。标记 transport_notice / local / git_sync，绝不当产品候选。`git-transport-<64hex>.md` 及 `git-transport-response-<64hex>.md` 为保留的本机文件名：发布快照排除它们，远端快照带这些文件会拒收；本地多出的输入通知不影响正常导入，真实碰撞仍不覆盖。

queue 本机处理通知时仍要履行绑定报告和 ack 合约：写 reviews/git-transport-response-<Queue-Event-ID>.md，保留三行身份并标本地范围，然后 ack。这份响应也不出口到对方。联合假 queue + 真实临时 Git 测试确认一个本机通知仅派发一次、绑定响应和 ack 完整、Git 另一端不收到通知或响应，不会因此被唤醒。

历史候选放错目录但尚未发布的通知也排除。已经推到历史分支的错误通知需要保留证据并协商迁移/处理，不能偷偷删记录或强推隐藏。

非阻断建议一并处理：本机通知发布失败不算去重完成；锁可用后会再尝试发布，已有记录的 OS 尝试不会重复。配置说明提醒 30 秒是单个远程命令的默认超时，首次较大 fetch 可在初始化前选择更长值。
